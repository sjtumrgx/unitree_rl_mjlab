# G1 Parkour Deployment Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add an isolated `deploy/robots/g1_parkour` runtime and a matching `simulate/build/unitree_mujoco_parkour` simulator path that can run the provided depth-conditioned parkour model with terrain assets and a live depth-camera window.

**Architecture:** Reuse the existing G1 deploy/runtime structure, but stage parkour artifacts into a dedicated policy tree with a generated deploy contract, then add a parkour-specific deploy-side depth provider plus a two-stage ONNX runner (`depth_encoder` -> `actor`). On the simulator side, add a second executable that loads a parkour scene XML, renders a torso-mounted depth camera, publishes organized PointCloud2 over DDS for the deploy controller, and shows a separate depth-view window.

**Tech Stack:** C++17, MuJoCo, GLFW/OpenGL, Unitree DDS wrappers, ONNX Runtime, Python 3, PyYAML, pytest.

### Task 3: Add the dedicated `g1_parkour` deploy runtime

**Files:**
- Create: `deploy/robots/g1_parkour/CMakeLists.txt`
- Create: `deploy/robots/g1_parkour/main.cpp`
- Create: `deploy/robots/g1_parkour/config/config.yaml`

- Create: `deploy/robots/g1_parkour/include/Types.h`
- Create: `deploy/robots/g1_parkour/src/State_RLBase.cpp`
- Create: `deploy/robots/g1_parkour/src/ParkourDepthProvider.cpp`
- Create: `deploy/robots/g1_parkour/src/ParkourObservations.cpp`

**Step 1: Mirror the existing G1 deploy layout**

Use `g1_antifall` / `g1_getup` as structure references, but keep all parkour-specific logic isolated under `deploy/robots/g1_parkour`.

**Step 2: Implement a two-stage ONNX runtime**

The new runner should:
- accept `proprio` + stacked `depth_image` observations,
- reshape depth input to `[1, 8, 18, 32]`,
- run `0-depth_encoder.onnx`,
- concatenate the resulting latent with the proprio vector,
- run `actor.onnx`,
- output the 29D action vector.

**Step 3: Implement the parkour depth provider**

The provider should:
- subscribe to an organized PointCloud2 topic from the simulator,
- read `z` depth per pixel,
- normalize/clamp to the configured range,
- apply the training crop region,
- maintain the raw history buffer of 37 frames,
- emit the 8-frame stack using skip=5 into `robot->data.named_observations["depth_image"]`.

**Step 4: Register the parkour depth observation**

Add a local observation term so the deploy `ObservationManager` can request the flattened stacked depth tensor.

**Step 5: Build the deploy target**

Run:
- `cmake -S deploy/robots/g1_parkour -B deploy/robots/g1_parkour/build`
- `cmake --build deploy/robots/g1_parkour/build -j4`

Expected: `deploy/robots/g1_parkour/build/g1_parkour_ctrl` is produced.
